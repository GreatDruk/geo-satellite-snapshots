# Источники иллюстраций README

Иллюстрации используют реальные снимки и сохранённые результаты проекта. Генеративные изображения и новые предсказания для оформления не создавались. Машиночитаемые источники, метрики, ID снимков и исходные ответы моделей сохранены в [sources.json](sources.json).

| Файл | Источник и контекст |
| --- | --- |
| `train_val_examples.png` | Без изменений восстановлен из `docs/train_val_examples.png`, commit `dd9dbf0a40ef515f8a481aa075e2d7ca1019d4c8`. Примеры шести классов из исходных train и val. ID и метки проверены по CSV предоставленного датасета. |
| `hard_target_shift_profiles.png` | Без изменений восстановлен из `docs/hard_target_shift_profiles.png`, commit `04259a7f0cf126aaaf71af3bf4e421990c06cf1a`. Preview шести профилей на train-изображении, а не измерение качества модели. |
| `global_local_examples.png` | Без изменений восстановлен из `docs/global_local_examples.png`, commit `87b03fd5e0d71dab82bca37790f6b9cf66a8e152`. Исторические full/crop predictions ResNet101 на val: `1977.jpg`, `3201.jpg`, `6146.jpg`. |
| `validation_results.png` | Построен в Matplotlib по выбранным строкам корневого `experiments.csv`. Run ID перечислены в основном README. Пустые `val_accuracy` финальных train+val refit не используются. |
| `fusion_cases.png` | Построен в Matplotlib из исходных val-фотографий и всех семи изменений в сохранённой HTML-таблице исторического ноутбука. Никакого повторного inference. Метки каждой фотографии сверены с `val.csv`. |
| `expert_routing_cases.png` | Построен в Matplotlib из исходных val-фотографий и всех четырёх изменений ансамбля `reference_101_50d4` после обученных попарных экспертов. Ответы перенесены из сохранённой таблицы ноутбука 08; истинные классы сверены с `val.csv`. |
| `water_routing_cases.png` | Построен в Matplotlib из четырёх val-фотографий и сохранённых ошибок исходного ResNet101 без TTA. Иллюстрирует маршрут по top-1; предсказаний обученного эксперта воды здесь нет. Истинные классы сверены с `val.csv`. |

Исходные фотографии для `fusion_cases.png` взяты из [архива, предоставленного пользователем](https://drive.google.com/file/d/1sbnKeVmiOmT4ZZHIbXIxuBWF9CQLWt6s/view). Источник таблиц — [исторический ноутбук 18_probability_fusion.ipynb](https://github.com/GreatDruk/geo-satellite-snapshots/blob/a9e7bcd1a8597d3d0dd32b95267d3ce82d5c5521/notebooks/18_probability_fusion.ipynb), commit `a9e7bcd1a8597d3d0dd32b95267d3ce82d5c5521`: ячейка 2 содержит метрики, ячейка 4 — таблицу семи изменений и две исходные галереи. Нумерация ячеек здесь начинается с нуля. Текущая версия без сохранённых outputs находится в [archive/notebooks/18_probability_fusion.ipynb](../../archive/notebooks/18_probability_fusion.ipynb).

В этом сравнении AGMFA — train-only B, checkpoint `best_loss` эпохи 22 с cosine `T_max=24`. Прежний ансамбль — 50% ResNet101 без TTA и 50% ResNet50 stronger с D4. Смесь — 50% AGMFA и 50% прежнего ансамбля. Это историческая проверка на 699 val-объектах; она отличается от нового рецепта `final/` с двумя моделями по 25 эпох и Geometry-4.

Подписи вероятностей в новой галерее округлены до целых процентов, как в исходных фигурах. Метрики в `sources.json` перенесены с точностью сохранённой таблицы, а не выданы за повторно рассчитанные значения из отсутствующих NPZ.

Результаты попарных экспертов взяты из [выполненного исторического ноутбука 08](https://github.com/GreatDruk/geo-satellite-snapshots/blob/aab772368dff801fb597ea9c06feee1f1cdb302b/notebooks/08_frozen_pairwise_experiments.ipynb), commit `aab772368dff801fb597ea9c06feee1f1cdb302b`: ячейка 7 содержит итоговые метрики, отдельную бинарную диагностику и routing summary, ячейка 9 — все изменения относительно обеих баз. В `expert_routing_cases.png` показаны все изменения относительно двухмодельного ансамбля: `12684.jpg`, `2200.jpg`, `7548.jpg`, `9099.jpg`. Обучены три train-only logistic regression на 2048 замороженных признаках ResNet101; новые нейросети в этом запуске не обучались. Схема в основном README соответствует реально проверенному маршруту по исходным top-2. Текущая версия — [archive/notebooks/08_frozen_pairwise_experiments.ipynb](../../archive/notebooks/08_frozen_pairwise_experiments.ipynb).

Таблица потенциального каскада взята из [исторического ноутбука 06](https://github.com/GreatDruk/geo-satellite-snapshots/blob/8f1ab748fa7fb2813258a25210937d2b2fb4e29c/notebooks/06_tta_ensembles.ipynb), commit `8f1ab748fa7fb2813258a25210937d2b2fb4e29c`, ячейка 6. Это аудит исходного ResNet50 stronger: маршрут по предсказанному top-1, без обучения специалистов и без измерения их ответов.

Ответы в `water_routing_cases.png` взяты из [docs/resnet101_review_audit.json](https://github.com/GreatDruk/geo-satellite-snapshots/blob/bd8cbdb61a3353efeeedf82d719f48142d62c5fe/docs/resnet101_review_audit.json), commit `bd8cbdb61a3353efeeedf82d719f48142d62c5fe`, поле `resnet101_errors`. Изображения: `7790.jpg`, `13048.jpg`, `12223.jpg`, `8698.jpg`. Здесь классификатор — ResNet101, а не ResNet50 из таблицы аудита: фотографии иллюстрируют ограничения того же принципа маршрутизации. Уверенность softmax округлена до целых процентов. Тип маршрута определён по сохранённому top-1; истинная метка используется только для описания ошибки.
