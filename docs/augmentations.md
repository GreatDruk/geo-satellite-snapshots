# Аугментации для CNN и протокол сравнения

Train чистый, val/test содержат искажения съёмки (из описания соревнования). Поэтому проверяем устойчивость к ориентации, цветопередаче и качеству. Это гипотезы для экспериментов: реальные уровни шума/размытия не измерялись, совпадение с распределением val/test не гарантируется. Test не используется для подбора параметров.

## Порядок запусков

02_baseline_cnn.ipynb оставлен для baseline_cnn.json: простая CNN без аугментаций.
04_augmentations.ipynb запускает один выбранный эксперимент, показывает train-примеры, логи и кривые.

| Конфиг | Изменения train |
| --- | --- |
| cnn_256_no_aug.json | Без аугментаций; контроль для новой серии |
| cnn_256_geometry.json | Отражения и случайные повороты на 0/90/180/270° |
| cnn_256_photo.json | Геометрия + умеренные brightness/contrast/saturation/hue и gamma |
| cnn_256_domain_shift.json | Всё выше + шум, blur, JPEG, снижение детализации |

Во всех четырёх одинаковы модель, seed=42, batch=32, 45 эпох, AdamW (LR=0.0007, weight_decay=0.005), cosine (T_max=45, eta_min=0.000005), нормализация mean=std=[0.5,0.5,0.5]. Меняется только augmentation и описание notes.
Каждому запуску нужен новый exp_id. Pipeline сохраняет конфиг, history.csv, графики, best/last checkpoints, предсказания val и строку experiments.csv.
Сравнивайте лучшую Accuracy на одной и той же исходной val. Не приписывайте различия между baseline_cnn и этими рецептами только аугментациям: архитектуры разные.
Сначала no_aug/geometry, потом photo/domain_shift. После выбора кандидата полезно повторить лучшие варианты с несколькими одинаковыми seeds, чтобы отличить устойчивое улучшение от случайности. Четыре рецепта используют одну val; это не независимая оценка финальной модели.

## Архитектура

Серия основана на cnn_256_balanced: 6 Conv3×3, каналы 24/48/96/192; по две свёртки в блоках 48 и 96. Conv без bias, затем BatchNorm и ReLU; MaxPool2×2 после каждого блока:
256 → 128 → 64 → 32 → 16. Затем AvgPool4×4 → Flatten3072 → Linear256 → ReLU → Dropout0.4 → Linear20.
Padding=1 сохраняет пространственный размер внутри свёрток. Выход — logits, без Softmax перед CrossEntropy. Всего 1 114 892 обучаемых параметра.
Нормализация входа фиксированная, BatchNorm обучается только на train; при val модель использует eval. Dropout и weight decay ограничивают переобучение.
Это разумная исходная ёмкость для 4999 изображений, а не доказанный оптимум.
cnn_256_balanced теперь совпадает с geometry по рецепту, а cnn_256_deeper — отдельная более ёмкая альтернатива (8 Conv, 60 эпох); её сравнение меняет архитектуру.
Уменьшенные CNN 96/128 перенесены в configs/archive/. Все активные CNN получают 256×256. MLP и pretrained-конфиги не менялись.

## Параметры augmentation

Все операции необязательны; {} полностью отключает аугментации. Для вложенной операции p по умолчанию 0. Неизвестные поля и некорректные диапазоны вызывают ValueError до обучения.
Операции реализованы на существующих PIL/NumPy/torch; torchvision для них не требуется. Python random и NumPy используют set_seed и seed_worker существующего pipeline.

| Поле | Значение в полном рецепте | Смысл |
| --- | --- | --- |
| horizontal_flip / vertical_flip | 0.5 / 0.5 | Вероятность каждого отражения |
| random_rotate90 | 1.0 | Вероятность выбрать один из четырёх равновероятных поворотов, включая 0°; нужен квадратный вход |
| color_jitter.p | 0.8 | Вероятность цветовых изменений в случайном порядке |
| brightness / contrast / saturation | 0.15 | Коэффициент равномерно из [0.85,1.15], отдельно для каждого изменения |
| hue | 0.02 | Сдвиг тона ±0.02 оборота цветового круга |
| gamma | p=0.25, range=[0.85,1.15] | Нелинейное изменение яркости: x ** gamma для x в [0,1] |
| gaussian_noise | p=0.35, std=[0.005,0.025] | Независимый аддитивный RGB Gaussian noise; std в единицах [0,1], примерно 1.3–6.4 уровней из 255 |
| gaussian_blur | p=0.25, sigma=[0.2,1.0] | Gaussian blur; radius PIL в пикселях |
| jpeg_compression | p=0.25, quality=[60,95] | Сжатие/декодирование в памяти; качество — целое число |
| resolution_degradation | p=0.2, scale=[0.65,1.0] | Полный кадр временно уменьшается до 166–256px и восстанавливается до 256px; crop нет |
| corruption_probability | 0.65 | Вероятность вообще рассматривать искажения качества для данного изображения |
| max_corruptions | 2 | Из прошедших свои p операций качества случайно выбираются максимум две |

Corruption gate и бюджет относятся только к resolution_degradation, gaussian_blur, jpeg_compression, gaussian_noise. Цвет, gamma и геометрия не входят в этот бюджет.
p операций качества — условные вероятности: глобальный gate и бюджет дополнительно уменьшают их фактическую частоту. Часть кадров остаётся без искажений качества.
Порядок: геометрия → цвет/gamma → снижение детализации → blur → JPEG → noise → tensor → нормализация. На val/test выполняются только RGB, необходимый resize, tensor и фиксированная нормализация.

Снижение детализации — отдельная train-аугментация для моделирования меньшего разрешения съёмки, а не постоянный уменьшенный вход CNN. Оно сохраняет весь обзор. При обычной загрузке image_size=256 исходных 256×256 resize пропускается.
rotation_degrees оставлен для совместимости: угол из [-degrees,degrees]; отражённое дополнение краёв убирает чёрные углы. Такие произвольные повороты частично заменяют содержимое углов отражением; новые рецепты вместо них используют точные повороты на 90°.
Новые операции выполняются до нормализации и не меняют файлы исходного датасета. Шум обрезается до допустимого диапазона [0,1].

## Почему умеренные искажения

Слишком сильный hue меняет цветовые признаки класса; сильный blur или crop может уничтожить небольшой объект. В рецептах нет crop, RandomErasing/Cutout, деформаций перспективы, инверсии и тяжёлой имитации облаков. MixUp/CutMix требуют другого режима меток/loss и пока не включены. Специфический SAR speckle не включён без сведений о типе сенсора.
Умеренная цветовая вариативность и blur — стандартные операции: [ColorJitter](https://docs.pytorch.org/vision/main/generated/torchvision.transforms.ColorJitter), [примеры transforms](https://docs.pytorch.org/vision/stable/auto_examples/transforms/plot_transforms_illustrations.html).
Конкретные диапазоны здесь выбраны как осторожные стартовые гипотезы, а не взяты как оптимальные из документации.

preview_augmentations показывает оригинал и случайные train-варианты, восстанавливает Python/NumPy RNG после просмотра. Изображение выбирается только из train. Можно пропустить эту ячейку; обучение повторно фиксирует seeds.
Одинаковый seed воспроизводит CPU-преобразования при неизменных настройках загрузчика; изменение num_workers или окружения меняет последовательность. deterministic_warn_only=true на CUDA не гарантирует побитовую повторяемость неподдерживаемых операторов.

## Проверки реализации

32 теста: 30 прошли, 2 пропущены (CUDA недоступна, torchvision отсутствует локально).
Проверены каждый тип искажения, p=0, corruption gate/бюджет, неизменность входного изображения, отсутствие аугментаций и потребления RNG на val, воспроизводимость, preview, совпадение рецептов вне augmentation и прямой/обратный проход всех активных CNN на 256.
Полный synthetic CNN-run проверяет логи, checkpoints, графики, журнал и отсутствие чтения test.
