# Как устроены конфиги экспериментов

Конфиг — обычный JSON: ключи объектов можно переставлять, но порядок элементов `model.layers` определяет порядок слоёв. Комментарии и запятая после последнего элемента в JSON не разрешены. `false`, `true`, `null` пишутся строчными буквами.

## Разделы

| Раздел / поле | Что задаёт |
| --- | --- |
| `seed` | Seed для инициализации весов, случайных аугментаций и загрузчиков |
| `notes` | Текст для строки в experiments.csv |
| `data` | Размер входа, нормализацию, аугментации и загрузку данных |
| `model` | Название модели, флаг pretrained и список слоёв |
| `training` | Эпохи, optimizer, scheduler, устройство и логирование |

Имя запуска `exp_id` удобно передавать из notebook. Его также можно задать в конфиге; аргумент функции имеет приоритет.

## Данные и размер изображения

- `raw_dir`: путь к неизменяемым данным относительно корня проекта.
- `image_size`: размер **после загрузки**, который получает модель. `256` эквивалентно `[256, 256]`; список задаётся как `[height, width]`. Если размер исходника совпадает, resize пропускается. Если поставить `64`, исходник 256×256 будет уменьшен в памяти до 64×64, а файл останется прежним.
- `batch_size`: количество изображений в одном шаге optimizer.
- `num_workers`: процессы загрузки; `0` загружает в основном процессе.
- `pin_memory`: закреплённая память для передачи на GPU.
- `normalization.mean/std`: три числа для RGB; применяется `(pixel / 255 - mean) / std`. `[0.5, 0.5, 0.5]` переводит диапазон [0, 1] в [-1, 1]. Это фиксированные настройки, не оценённые на test.
- `augmentation`: `{}` отключает изменения. Пример: `{"horizontal_flip": 0.5, "vertical_flip": 0.5, "rotation_degrees": 15}`. Flip-параметры — вероятности, угол выбирается из [-15, 15]. Применяется только к train. Значения в этом примере иллюстративные, их полезность надо проверять экспериментами.

Входной тензор имеет форму `[B, 3, H, W]`: batch, RGB-каналы, высота, ширина.

## Сборка модели

`model.name` — `mlp` или `cnn` для встроенного конструктора. Название не добавляет слои автоматически: архитектуру целиком задаёт `layers`. `pretrained=false` означает обучение с нуля. Для ResNet есть встроенный адаптер: см. [transfer_learning.md](transfer_learning.md). Остальные внешние архитектуры подключаются через `model_factory`.

Минимальный MLP:

```json
{
  "name": "mlp",
  "pretrained": false,
  "layers": [
    {"type": "flatten"},
    {"type": "linear", "out_features": 256},
    {"type": "relu"},
    {"type": "dropout", "p": 0.3},
    {"type": "linear", "out_features": "num_classes"}
  ]
}
```

Каждый элемент списка превращается в один слой `nn.Sequential`. Слои выполняются сверху вниз. Чтобы добавить ещё один скрытый слой, вставьте `linear` и активацию перед последним `linear`. Последний слой должен выдавать ровно число классов; `"num_classes"` подставляется из `classes.csv` (сейчас 20).

`in_features`, `in_channels`, `num_features` вручную не указываются: их вычисляет конструктор по выходу предыдущего слоя. Для этих автоматически задаваемых аргументов не добавляйте дублирующие поля в JSON.

| `type` | Параметры | Действие |
| --- | --- | --- |
| `conv2d` | `out_channels`, `kernel_size`; опционально `stride`, `padding`, `dilation`, `groups`, `bias` | Пространственные фильтры; меняет каналы и иногда H/W |
| `max_pool2d` | `kernel_size`; опционально `stride`, `padding`, `dilation` | Уменьшает H/W, сохраняет число каналов; `ceil_mode=true` конструктор не поддерживает |
| `adaptive_avg_pool2d` | `output_size`, например `[4, 4]` | Приводит H/W к указанному размеру, сохраняет каналы |
| `batch_norm2d` | Опционально `eps`, `momentum`, `affine`, `track_running_stats` | Нормализует каналы пространственного тензора |
| `flatten` | Без дополнительных параметров | `[B, C, H, W]` → `[B, C*H*W]` |
| `linear` | `out_features`; опционально `bias` | Полносвязный слой; требует предварительного flatten для пространственного входа |
| `dropout` | `p` — вероятность зануления, например 0.3 | Регуляризация при обучении; при оценке выключается |
| `relu`, `gelu`, `silu`, `sigmoid`, `tanh`, `leaky_relu` | Обычно без параметров; для leaky_relu можно `negative_slope` | Нелинейная активация; размер тензора не меняется |

Параметры передаются в соответствующие слои PyTorch. Для пространственных размеров используйте число или пару чисел (например `kernel_size: [3, 5]`); `padding` здесь должен быть числовым, а не строкой `"same"`. Не включайте `return_indices` в MaxPool: следующий слой ожидает тензор.

Обычный CNN-блок:

```json
[
  {"type": "conv2d", "out_channels": 32, "kernel_size": 3, "padding": 1},
  {"type": "batch_norm2d"},
  {"type": "relu"},
  {"type": "max_pool2d", "kernel_size": 2}
]
```

Это фрагмент списка `layers`, а не целый конфиг. Повторяйте такие блоки с нужным количеством каналов, затем добавляйте pooling/flatten/linear для классификации. После flatten пространственные conv/pool больше не подходят. BatchNorm2d располагается до flatten. Последний Linear оставляйте без активации: CrossEntropyLoss получает сырые logits. Softmax в архитектуру добавлять не надо.

Сборщик поддерживает последовательные архитектуры. Residual-связи и разветвления (например настоящая ResNet) нельзя описать простым списком: их реализует будущая фабрика модели.

## Как учитывать размеры

Для conv/pool по одной пространственной оси используется:

```text
out = floor((in + 2*padding - dilation*(kernel_size-1) - 1) / stride + 1)
```

`conv2d` с kernel=3, padding=1, stride=1 сохраняет H/W. `max_pool2d` с kernel=2 и стандартным stride=2 делит чётный размер пополам. Активации, dropout и BatchNorm2d сохраняют форму.

Текущий baseline CNN при `image_size=256`:

| После слоя | Форма без batch |
| --- | --- |
| Вход | 3 × 256 × 256 |
| Conv 16 + ReLU | 16 × 256 × 256 |
| MaxPool 2 | 16 × 128 × 128 |
| Conv 32 + ReLU | 32 × 128 × 128 |
| MaxPool 2 | 32 × 64 × 64 |
| Conv 64 + ReLU | 64 × 64 × 64 |
| AdaptiveAvgPool [4,4] | 64 × 4 × 4 |
| Flatten | 1024 |
| Linear 128 + ReLU + Dropout | 128 |
| Linear num_classes | 20 |

Размеры Linear считает код. Вам нужно выбирать разумный порядок слоёв и следить, чтобы pooling не уменьшал изображение до нулевого размера. Перед запуском выполняется проверочный forward; ошибки формы обнаруживаются до создания артефактов.

У MLP при 256×256 Flatten даёт `3*256*256 = 196608` признаков. Первый Linear с 256 нейронами содержит `196608*256 = 50331648` весов плюс bias. При 64×64 — `12288*256 = 3145728` весов. Уменьшение входа снижает стоимость, но теряет детали. Сейчас оба конфига используют 256; выбор другого размера оформляется отдельным экспериментом.

Если поменять размер входа MLP, меняется форма первого Linear и старые веса уже не подходят. В текущей CNN adaptive pooling сохраняет размер входа Linear при изменении H/W, но при inference всё равно используйте preprocessing сохранённого конфига.

## Обучение и optimizer

`epochs` задаёт число проходов по train. `log_every=2` печатает каждую вторую эпоху, а также первую и последнюю. Метрики сохраняются для всех эпох. `device="auto"` выбирает CUDA, если доступна, иначе CPU. `deterministic=true` включает строгую детерминированность.

```json
"optimizer": {
  "name": "adam",
  "lr": 0.001,
  "weight_decay": 0.0001
}
```

`lr` — начальная скорость обучения. `weight_decay` — регуляризация весов. Поддерживаются `adam`, `adamw`, `sgd`, остальные параметры передаются конструктору PyTorch. Например для SGD можно добавить `momentum: 0.9`; для Adam — `betas: [0.9, 0.999]`.

## Scheduler

Optimizer обновляет веса на каждом batch. Scheduler меняет LR **между эпохами**, после validation. В baseline-конфигах он явно выключен:

```json
"scheduler": null
```

Вместо null можно поставить один из объектов ниже, внутри `training`, рядом с `optimizer`.

```json
"scheduler": {"name": "step", "step_size": 5, "gamma": 0.5}
```

Каждые 5 завершённых эпох умножает LR на 0.5: эпохи 1–5 используют исходный LR, эпоха 6 — половину.

```json
"scheduler": {"name": "cosine", "T_max": 20, "eta_min": 0.000001}
```

Меняет LR по косинусной кривой до eta_min за 20 шагов scheduler. При отсутствии T_max используется число epochs. Здесь нет автоматических перезапусков; для одного плавного снижения ставьте T_max равным epochs.

```json
"scheduler": {
  "name": "plateau",
  "monitor": "val_loss",
  "factor": 0.5,
  "patience": 2,
  "min_lr": 0.000001
}
```

Уменьшает LR, когда выбранная validation-метрика перестаёт улучшаться. `patience=2` допускает две эпохи без улучшения; снижение происходит при следующей неудачной эпохе. Для `val_loss` автоматически ставится mode=min, для `val_accuracy` — mode=max. Противоречащий метрике mode отклоняется. Порог улучшения можно настроить параметрами threshold/threshold_mode PyTorch. Test-метрики не поддерживаются.

В history.csv `learning_rate` — LR, использованный в данной эпохе, `next_learning_rate` — LR после scheduler.step(). График показывает первый из них. Состояния optimizer и scheduler сохраняются после шага scheduler; это не заменяет сохранение RNG для точного продолжения обучения.

Официальная документация: [StepLR](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.StepLR.html), [CosineAnnealingLR](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.CosineAnnealingLR.html), [ReduceLROnPlateau](https://docs.pytorch.org/docs/stable/generated/torch.optim.lr_scheduler.ReduceLROnPlateau.html).

## Изменение конфига в notebook

```python
from src.experiment import load_config, run_experiment

config = load_config("configs/baseline_cnn.json")
config["training"]["scheduler"] = {"name": "step", "step_size": 5, "gamma": 0.5}
config["notes"] = "CNN 256, StepLR каждые 5 эпох"
result = run_experiment(config, exp_id="cnn_256_step_001")
```

Для нескольких экспериментов лучше сохранять отдельные JSON-файлы. Каждый фактически использованный конфиг автоматически копируется в artifacts/logs/<exp_id>/config.json. Названия scheduler можно также записывать как steplr, cosineannealinglr, reducelronplateau; регистр имени не важен.
