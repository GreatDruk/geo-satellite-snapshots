## Что означает история обучения

Уже после первой эпохи обучения только головы Accuracy95.28%, loss0.2477. Позже train Accuracy достигает100%, loss около0.0005–0.0007, а val остаётся около95–96%. У исходной101 val loss0.1633. Это согласуется с ухудшением обобщения и избыточной уверенностью ошибок при дообучении. Больше эпох не выглядит обоснованным лечением.

При расширении головы использована инициализация `[W_old, 0]`: до обновлений дополнительная max-ветвь не меняет исходный классификатор. Однако исходные признаки не делают дальнейшее обучение автоматически полезным. Эксперимент совмещает новый pooling и продолжение оптимизации; контроля «ещё12 эпох с прежним average» нет. Поэтому вывод — этот конкретный рецепт не помог; универсальную бесполезность max-pooling мы не доказали. Предыдущая гипотеза не оправдалась, новый кандидат исключаем из финального рецепта.

## Следующий один запуск: специалист зданий

Цель — изменить задачу обучения на различение `church / palace / commercial_area`, вместо повторного обучения той же общей задачи на20 классов. В текущем ансамбле6 ошибок church и2 palace находятся внутри этой группы. Часто это уверенные ошибки: church10647 предсказывается как palace с вероятностью0.999999. Маршрут только по низкой уверенности их пропустит.

Группа воды менее выгодна:4 ошибки при136 правильных ответах под риском. Площадки требуют маршрута, который сейчас пропускает3 целевые ошибки. Поэтому не обучаем три специалиста одновременно.

### Протокол специалиста

1. ResNet50, backbone из собственного stronger checkpoint, новая голова на4 класса: church, palace, commercial_area, other. Новая голова меняет обучаемое различение; прежняя почти безошибочная на train20-классовая голова не переносится.
2. Все749 train-снимков зданий; остальные4250 доступны как other. Сбалансировать четыре группы при sampling, внутри other выбирать примеры из всех17 исходных классов. Не ограничивать отрицательные примеры только найденными val-ошибками. Val не становится обучающей выборкой.
3. Вход256, полный кадр, прежние аугментации stronger с сохранением контекста. Без дополнительного усиления blur и присвоения метки здания произвольному маленькому crop.
4. Один seed42, ориентир20 эпох:2 для новой головы, затем partial layer3/layer4; BN backbone заморожен. Стартовый AdamW: body1e-5, head1e-4, weight_decay0.001, cosine; dropout0.3. Это исходный протокол одного эксперимента, а не обещание оптимальных параметров или сетка.
5. Сохранить4-классовые val probabilities, веса и историю. Оценить также итоговый20-классовый pipeline на всех699 снимках. Accuracy специалиста на своей группе нельзя выдавать за метрику соревнования.

### Как применять без истинных меток

Reference остаётся текущий ансамбль. Специалист вызывается, если **предсказанный** reference класс входит в группу зданий. Если specialist argmax=other, оставить reference. Иначе перераспределить только вероятность внутри группы, сохранив суммарную массу группы и все внешние вероятности.

Первое фиксированное правило: `p_new(c)=0.25*p_global(c)+0.75*P_global(G)*q_conditional(c)` для трёх классов G, где `q_conditional(c)=q(c)/sum(q(G))`; вне G вероятности прежние. Коэффициент0.75 выбран заранее, не подобран по val. Слабая добавка специалиста не сможет изменить почти единичную уверенность общей модели. Четырёхклассовые probabilities нельзя напрямую усреднять с20-классовыми.

Принимать специалиста только при положительном балансе исправленных/испорченных ответов **всего pipeline**. В отчёте обязательно отдельно показать97 правильных маршрутизированных примеров и2 внешних ложных попадания. Если улучшения нет, сохраняем reference; не запускаем водный специалист по инерции. Следующий резерв — отдельная обучаемая global/local модель с общей меткой набора views, но её более дорогой запуск сейчас не первый приоритет.

## Что готово и что потребуется реализовать

Аудит и план выполнены; текущий manifest в99 сохранён. Новые веса Average+Max для дальнейшего выбора не нужны. Код обычного20-классового обучения уже работает, но он **не поддерживает этот специалист одним JSON**: текущая загрузка checkpoint требует одинаковых классов. Перед Kaggle нужны отображение20→4, sampler, загрузка backbone без старой головы, сохранение4-классовых probabilities и описанный composite inference с глобальной оценкой. Не следует запускать псевдоконфигурацию, которая просто переименует классы без этих изменений.

Фактические результаты, первоначальные predictions и experiments.csv не изменены. Test не использован ни для fitting, ни для выбора правил. Последовательные решения на одной val остаются результатами на этой val; максимальный test/public score и исправление всех20 ошибок не установлены.
