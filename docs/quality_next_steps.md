## Решение

Обновление после завершённой ResNet101: лучшая одиночная модель теперь101 (678/699, 97.00%). Смешанный ансамбль101 none + stronger50 D4 даёт679/699 (97.14%), но исправляет всего один дополнительный ответ. TTA101 ещё не измерено — это следующий шаг без обучения. Девять ошибок101 внутри church/palace/commercial_area сохраняются, поэтому следующим целевым обучением может быть один специалист этой группы. Подробный разбор: [resnet101_review.md](resnet101_review.md). Ниже сохранено обоснование исходного плана до101.

Сохраняем ResNet50 partial stronger (675/699, 96.57%) как опорную модель. Сначала используем уже оплаченные обучения: TTA и soft ensemble. Следующее новое обучение — один ResNet101 partial с лучшим текущим набором искажений. Специалист зданий — резервный второй запуск при сохранении соответствующей путаницы, а не три специалиста сразу. Full, повтор seeds, сетка мелких LR/dropout/epochs не входят в основной план.

## 1. TTA и ансамбль: без нового обучения

- Загрузить best checkpoints mild и stronger; получить probabilities на val для original/H/V/HV. Усреднять вероятности преобразований, не argmax-метки. Нормализация та же ImageNet, размеры 256, модель в eval, без обновления BN.
- Измерить отдельно stronger, stronger+TTA и равновесный soft ensemble mild/stronger+TTA. Не подбирать десятки весов ансамбля. Если усреднение ухудшает val, сохранить лучший одиночный вариант.
- Mild исправляет 6 ошибок stronger, stronger исправляет 9 ошибок mild, 18 ошибок общие. Это причина проверить объединение. Oracle 681/699=97.42% — недостижимая гарантия, не прогноз результата усреднения; ансамбль может потерять правильные ответы.
- Дополнительные повороты 90/180/270° дают восемь уникальных ориентаций с отражением (D4). Это второй дешёвый inference-вариант при желании, не повторное обучение. Обученные модели не видели явного random_rotate90; расширенный TTA может как помочь, так и ухудшить. Сначала четыре знакомые ориентации.
- Старые CSV сохраняют только метки; probability inference теперь реализован и сохраняет NPZ с IDs/порядком классов/ground truth. Новые обучения также сохраняют val_probabilities.npz. В конце `06_tta_ensembles.ipynb` добавлены реальное TTA/ensemble, confidence/margin и ошибки выбранного рецепта. Для новых моделей доступны проверяемый cache старых вероятностей, парные и общий равновесные ансамбли без дополнительного inference для комбинаций.

## 2. Один новый общий кандидат: ResNet101 partial

Конкретный стартовый рецепт: configs/resnet101_partial_domain_shift_stronger.json, копия текущего resnet50_partial_domain_shift_stronger. Меняется только архитектура; сохранены IMAGENET1K_V2, input 256, layer3/layer4, frozen BN, warmup 3, 25 эпох, batch 32, AdamW backbone/head LR 5e-5/5e-4, weight decay 0.001, cosine, head dropout 0.3. Если batch 32 не помещается, это технический повод изменить batch, а не заранее уменьшать разрешение. Новый config уже выбран в 03_pretrained.ipynb; проверен настоящий CPU forward ResNet101 без скачивания pretrained weights.

Почему это обучение оправдано: ошибки резких снимков church/palace/commercial_area и lake/wetland требуют различать форму и контекст, а не только переносить более тяжёлый шум. Более глубокое pretrained-представление — содержательная гипотеза для этих случаев. Дополнительно новая модель может исправлять другие ошибки, чем ResNet50, и приносить пользу в ансамбле даже без выигрыша в одиночном Accuracy.

В [официальной таблице ResNet101 V2](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet101.html) ImageNet top-1 составляет 81.886%, GFLOPS 7.80; у [ResNet152 V2](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.resnet152.html) — 82.284%, 11.51. Это другой датасет и стандартный размер оценки, не прогноз нашей Accuracy или времени. Разница ImageNet между 101 и 152 невелика при более высокой вычислительной стоимости 152; при ограниченном числе запусков выбираем 101, не последовательную сетку 50→101→152. Если допустим ровно один существенно более тяжёлый запуск и бюджет на него свободен, 152 можно выбрать вместо 101, но гарантии превосходства на спутниковых снимках нет.

Оценивать candidate по val Accuracy и взаимодополнению с опорной моделью; включать в ensemble только по измеренному результату. Не обещать заранее 98–99%. Увеличение глубины не восстанавливает утраченную пикселизацией информацию и само по себе не увеличивает пространственное разрешение финальной feature map.

## 3. Что менять в аугментациях по ошибкам

На val видно два типа проблем:

| Наблюдение | Что имеет смысл | Чего ожидать не следует |
| --- | --- | --- |
| Сильное размытие, пикселизация (например, 1617, 1977, 10003, 12286) | Сохранить доказавшие пользу stronger blur/downscale, сочетать с JPEG/noise умеренной вероятности | Шум не восстановит потерянную форму объекта; не все такие снимки различимы |
| Резкие здания, church→palace/commercial_area | Более сильные признаки и сравнение train-примеров; позднее специалист зданий | Повышение blur/noise на каждом снимке не решает семантическую границу |
| Маленькая площадка среди жилья (6931, 8132) | Сохранить весь кадр 256 и различимые линии площадки; при отдельной будущей модели проверить whole-frame + локальный вид | Сильный случайный crop/erasing может удалить объект, upscale не добавляет деталей |
| Lake→wetland с водой и растительностью | Устойчивость к цвету/контрасту и более сильное различение контекста | Нельзя определять lake только по синему цвету; grayscale всегда может убрать полезный признак |

Не увеличиваем тяжесть всех операций одновременно. Текущий corruption gate оставляет часть примеров без разрушения деталей — это полезно для семантического различения. 90°-повороты без обрезания кадра — разумное дополнение геометрии спутниковых сцен, если понадобится следующий рецепт; не гарантированный прирост. Облака, большие маски и сильное размытие на каждом изображении сейчас не обоснованы. Случайные аугментации применяются только к train; данные raw не меняются.

## 4. Специалист / двухэтапный вариант

В ноутбуке рассчитан маршрут по текущему предсказанному классу:

| Группа | Переданных снимков | Уже правильных ответов под риском | Ошибки внутри группы, потенциально исправимые | Ошибки истинной группы, не попавшие в маршрут | Посторонних снимков, нужен reject |
| --- | --- | --- | --- | --- | --- |
| church/palace/commercial_area | 106 | 96 | 8 | 1 | 2 |
| lake/wetland | 69 | 66 | 3 | 1 | 0 |
| basketball_court/tennis_court | 67 | 65 | 2 | 3 | 0 |

Три идеальных специалиста без reject могут исправить максимум 13 текущих ошибок, но меняют 227 уже правильных ответов. Для зданий максимум 8 ответов (+1.14 п.п.) при безошибочном специалисте и отсутствии регрессий. Это объясняет приоритет зданий перед двумя маленькими задачами; не обещает такой прирост.

Если после ResNet101/TTA сохраняются ошибки зданий, обучить **одного** специалиста church/palace/commercial_area/other. Train содержит около 250 изображений каждого целевого класса; нужны также разнообразные отрицательные train-примеры остальных классов, включая похожие residential/station сцены. Не обучать специалиста на выбранных val-ошибках, не менять их метки. Инициализация из ImageNet или сохранённого checkpoint общей модели; для более тонкой задачи адаптировать поздние блоки, а не просто повторить argmax той же головы.

Жёстко заменять любой ответ общей модели внутри группы рискованно. После получения probabilities возможен маршрут по двум лучшим кандидатам и небольшой разнице их вероятностей, с решением other/reject; либо мягкое объединение. Для специалиста только на группе G нормированная оценка q относится к условному распределению внутри G: сначала вернуть его к общей массе P(G), затем смешать с исходными p. Нельзя сравнивать непосредственно его «0.99 внутри трёх классов» с вероятностями двадцатиклассовой сети. Вариант с other требует отдельной согласованной обработки оценки outside; не добавлять сырые logits разных моделей напрямую.

Ground truth не участвует в маршрутизации inference. Специалист зданий не решит church→medium_residential без более широкого маршрута; нельзя считать каскад автоматически лучше общего ансамбля. Все решения о включении компонента проверяются по итоговым 20-классовым predictions, включая испорченные ранее правильные ответы.

## Бюджет решений

1. Ноль новых обучений: inference TTA/soft ensemble существующих моделей.
2. Одно новое обучение: ResNet101 partial stronger.
3. Только при оставшейся соответствующей проблеме — второе обучение специалиста зданий. Вместо него возможна одна модель с сохранением более высокого пространственного разрешения features для малых объектов, но это отдельная архитектурная доработка, пока не реализованная.

После этого фиксировать лучший одиночный/ансамблевый pipeline и собирать `99_final_pipeline.ipynb`. Повторы seeds и широкий поиск не планируются. Test — только inference уже выбранного решения, без fitting/подбора параметров.
