# ResNet101: результаты и следующий шаг

Проверка 2026-10-05. Исходный запуск: `resnet101_partial_domain_shift_stronger_001`. Только val и сохранённые артефакты; test не читался, нового обучения и forward-pass не было.

## Корректность

Все 25 эпох завершены, history конечен. Journal, summary и history согласованы: best_epoch=21, Accuracy=678/699. Argmax probabilities точно совпадает с val.csv. Проверены 699 уникальных ID, классы, true labels, конечность и нормировка probabilities. В best.pt/last.pt проверены эпохи 21/25, best_epoch=21, голова 20×2048 и конечность плавающих model tensors. Повторный inference загруженных весов в эту проверку не входит.

ResNet101 и stronger50 совпадают по seed, данным, аугментациям, режиму partial и параметрам обучения; отличается архитектура. Оба обучались на Tesla T4. Partial у 101 обучает около 41.10 из 42.54 млн параметров — это уже адаптация большей части сети.

Остальные ошибки 101: railway, railway_station, sea_ice — по одной. Church/lake дают 11/21 ошибок. Church→palace: 4; church→commercial_area: 3; palace→commercial_area: 2. Ноль ошибок по истинному commercial_area/tennis_court не означает отсутствие ложных предсказаний этих классов.

Просмотрены все 21 изображение: [галерея](resnet101_errors.png), также добавлена в 05_error_analysis.ipynb.

- 1977/10003 (basketball), 4329/10472 (church) сильно размыты. Сохранять blur/down-upscale разумно; увеличивать разрушение деталей на большей доле train сейчас не обосновано.
- 10647/12684/12850 (church), 11562 (palace) достаточно резкие. Комплексы зданий и окружение похожи на конкурирующие классы; дополнительный blur эту границу не научит различать.
- 7790/10533/13048/13473 содержат воду и растительность. Для lake/wetland важен контекст, одного цвета воды недостаточно.
- 12301 — небольшое озеро среди светлых гор. 12223 визуально неоднозначен относительно исходной lake; проверить описание класса/train-примеры, а не автоматически менять метку.

Некоторые ошибки имеют confidence около 1. Каскад только для неуверенных примеров пропустит часть ошибок зданий. Их нельзя объяснить исключительно качеством фото или глубиной сети.

## Следующие действия

1. Основной одиночной моделью считать ResNet101 best.pt. Сохранить ResNet50 и новый ансамбль как кандидата по val; не объявлять ансамбль обязательной заменой за одно исправление.
2. Сначала inference ResNet101 flips/D4 на GPU, без нового обучения и повторов seed. run_validation_suite уже поддерживает эти режимы. Не устраивать длинную сетку весов на 699 val-снимках.
3. Следующий обучающий эксперимент, если нужен дополнительный прирост: **один специалист church/palace/commercial_area/other**, как в предыдущем плане. После101 условие для него сохраняется: девять ошибок внутри группы. Маршрут по предсказанному классу группы передаст 106 снимков: 96 уже правильных, 9 ошибок внутри группы, 1 посторонний railway_station. +9 ответов / +1.29 п.п. — только потолок идеального специалиста без регрессий, не ожидаемый результат.
4. Учить только на train, с разнообразными отрицательными классами; адаптировать поздние блоки, сохранять полный кадр256 и имеющиеся умеренные domain-shift аугментации. Использовать согласованное мягкое смешивание вероятностей и other/reject, оценивать итоговые20 классов и испорченные правильные ответы. Не жёстко заменять все ответы группы; не считать маршрут по top-2 или низкой уверенности достаточным заранее.

ResNet152, full, больше эпох и усиление всех искажений сейчас менее обоснованы, чем целевой специалист. Не запускаем одновременно специалистов воды/площадок и широкий поиск. После TTA/одного специалиста фиксируем pipeline; test — только inference выбранного решения.
